# Auth Service - Knowledge Transfer Document

## Overview
The Auth Service is a centralized authentication and authorization microservice built with FastAPI.
It handles all user login, token management, and permission validation across the platform.

## Architecture
The service uses JWT (JSON Web Tokens) for stateless authentication.
Tokens are signed using RS256 (RSA Signature with SHA-256).
The private key is stored in AWS Secrets Manager under the key: prod/auth/jwt-private-key.
The public key is distributed to all downstream services via an internal JWKS endpoint at /auth/.well-known/jwks.json.

## Token Lifecycle
Access tokens expire after 15 minutes.
Refresh tokens expire after 7 days.
Token refresh is handled silently by the frontend SDK - the user never sees it.
If a refresh token is expired, the user is redirected to the login page.
Refresh tokens are stored in an httpOnly cookie to prevent XSS attacks.

## Login Flow
1. User submits email and password to POST /auth/login
2. Password is verified against bcrypt hash stored in PostgreSQL (users table)
3. On success, an access token and refresh token are generated
4. Both tokens are returned - access token in response body, refresh token in httpOnly cookie
5. Failed login attempts are rate limited to 5 attempts per 15 minutes per IP

## Key Endpoints
- POST /auth/login        - Login with email and password
- POST /auth/refresh      - Get new access token using refresh token cookie
- POST /auth/logout       - Invalidate refresh token
- GET  /auth/me           - Get current user profile
- GET  /auth/.well-known/jwks.json - Public keys for token verification

## Database Schema
Table: users
- id (UUID primary key)
- email (unique, indexed)
- password_hash (bcrypt)
- role (enum: admin, editor, viewer)
- created_at, updated_at
- is_active (boolean, default true)

Table: refresh_tokens
- id (UUID primary key)
- user_id (FK to users)
- token_hash (SHA256 of the actual token)
- expires_at
- revoked_at (nullable - set when logout is called)

## Error Codes
- AUTH_001: Invalid credentials
- AUTH_002: Account disabled
- AUTH_003: Token expired
- AUTH_004: Token invalid or tampered
- AUTH_005: Refresh token revoked
- AUTH_006: Rate limit exceeded

## Common Issues and Fixes
Issue: Token verification failing in downstream services
Fix: Make sure downstream services are fetching the JWKS keys from the internal endpoint, not hardcoding the public key. Keys are rotated every 90 days.

Issue: Users getting logged out randomly
Fix: Check if the refresh token cookie domain is set correctly. It must match the top-level domain. Look at AUTH_COOKIE_DOMAIN env var.

Issue: Rate limiting too aggressive in dev
Fix: Set AUTH_RATE_LIMIT_ENABLED=false in local .env. Never disable in production.
